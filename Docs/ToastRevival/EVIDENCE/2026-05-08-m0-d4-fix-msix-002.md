# Evidence: FIX-MSIX-002 — ManifestMinVersion / Runtime Gate Reconciled

**Date:** 2026-05-08
**Milestone:** M0 D4 pre-work
**Commit:** (pending — commit after Abish QA)
**Author:** Anthony Catawampus

## Problem

`Package.appxmanifest` declared `TargetDeviceFamily MinVersion="10.0.17763.0"` (Win10 1809),
but `Program.cs` checked `OperatingSystem.IsWindowsVersionAtLeast(10, 0, 19041)` (Win10 2004).

A Win10 1809 machine would pass the MSIX install gate (`Add-AppxPackage` succeeds) but the agent
would exit 2 at runtime with the message "Toast Notification agent requires Windows 10 2004 / build
19041 or later." The user sees a healthy install and a silently failing agent — confusing UX for
MSPs triaging endpoint issues.

## Fix

Option (b) from FIX-LIST.md: bumped manifest MinVersion to match the runtime floor.

| File | Old | New |
|---|---|---|
| `Package.appxmanifest` | `MinVersion="10.0.17763.0"` | `MinVersion="10.0.19041.0"` |
| `Package.appxmanifest` | `Version="0.2.0.3"` | `Version="0.2.1.0"` |
| `ToastRevival.Agent.csproj` | `<TargetPlatformMinVersion>10.0.17763.0</TargetPlatformMinVersion>` | `<TargetPlatformMinVersion>10.0.19041.0</TargetPlatformMinVersion>` |
| `Program.cs` | "...for this spike." | "...or later." (removed internal jargon) |

## New behavior

- Win10 1809/1903/1909 endpoint: `Add-AppxPackage` fails immediately with "This app can't be
  installed because it requires Windows version 10.0.19041.0 or higher." No ambiguity.
- Win10 2004+ (build 19041+) / Win11: install succeeds, runtime gate passes, agent fires toast.
- MSI path unaffected: the runtime check in `Program.cs` already used 19041; MSI install has no
  MinVersion constraint.
