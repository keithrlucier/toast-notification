## FIX-M8C-001 — Cross-Tenant Audit Log Leak

The `AuditLog` entity has no global query filter on `AppDbContext`. The comment at line 123–129 says "AuditLog intentionally has no global filter — admins can query across tenants" — which is correct *for the PlatformAdmin SystemController* but not for the per-tenant `AuditController`. Both `List` and `Export` were querying `_db.AuditLogs.Where(l => l.Timestamp >= since)` with no tenantId predicate, leaking every tenant's audit rows to any authenticated tenant admin.

**Patch (10 insertions, 3 deletions):**

```csharp
// FIX-M8C-001: AuditLog has no global query filter (PlatformAdmin
// SystemController needs the cross-tenant view). Per-tenant audit
// endpoints must scope to the caller's tenantId explicitly.
var tenantId = Guid.Parse(User.FindFirstValue("tenantId")!);

var logs = await _db.AuditLogs
    .Where(l => l.TenantId == tenantId && l.Timestamp >= since)
    .OrderByDescending(l => l.Timestamp)
    ...
```

Same extraction pattern already in use elsewhere in the controller (`Export`'s tenantName lookup). Composite `(TenantId, Timestamp)` index exists at `AppDbContext.cs:127`.

Regression test: `SecurityTests.TenantIsolation_AuditList_DoesNotLeakOtherTenantsRows` seeds two tenants' audit rows and asserts only own-tenant data returns. Without the patch, the test would fail; with it, it passes.

**New standing sweep check (Carl):** "Does every entity without a global query filter have an explicit tenantId predicate at every per-tenant controller read site?" Folded into Code Sweep Step 5.

## SecurityHarness — Seed + JWT Forge

Distinct from `LoadHarness` in two ways: (1) the seeded admin's role is configurable (Technician / Admin / SuperAdmin probes need different role tokens), and (2) the returned record exposes the `Tenant` + `AppUser` rows themselves so individual tests can mutate state without re-querying.

```csharp
public sealed record SeededPenTenant(
    Guid TenantId,
    Tenant Tenant,
    string SigningKey,
    AppUser AdminUser,
    string AdminToken,
    IReadOnlyList<SeededPenDevice> Devices);

public static async Task<SeededPenTenant> SeedTenantAsync(
    ApiTestFactory factory,
    UserRole role           = UserRole.SuperAdmin,
    int deviceCount         = 0,
    bool isPlatformAdmin    = false,
    string tenantNamePrefix = "PenTest");
```

`ForgeUserJwt(factory, claims, expiresAt, signingKeyOverride, issuerOverride, audienceOverride)` mints arbitrary-claim JWTs. The production `TokenService` reads `IsPlatformAdmin` from the DB row, so it cannot forge platformAdmin claims for non-admin users — the pen-tests need that ability to verify the `JwtBearer` middleware rejects forgeries signed with the wrong symmetric key.

## WebSocketTransportTests — Closes INFO-M8A-003

Production agents use SignalR's default transport negotiation, which settles on WebSockets when both ends support it. Browsers can't set custom headers on a WS upgrade, so SignalR falls back to placing the access token in the URL query string — which is exactly what the `JwtBearerEvents.OnMessageReceived` event handler at `Program.cs:65-75` is responsible for picking up:

```csharp
opts.Events = new JwtBearerEvents
{
    OnMessageReceived = ctx =>
    {
        var token = ctx.Request.Query["access_token"].ToString();
        if (!string.IsNullOrEmpty(token) && ctx.Request.Path.StartsWithSegments("/hubs"))
            ctx.Token = token;
        return Task.CompletedTask;
    },
};
```

The test isolates this single seam:

```csharp
var wsClient = factory.Server.CreateWebSocketClient();
var connection = new HubConnectionBuilder()
    .WithUrl(hubUrl, opts =>
    {
        opts.Transports          = HttpTransportType.WebSockets;
        opts.SkipNegotiation     = true;     // no negotiate POST → no Authorization header path
        opts.AccessTokenProvider = () => Task.FromResult<string?>(device.Token);
        opts.WebSocketFactory    = async (ctx, ct) =>
            await wsClient.ConnectAsync(ctx.Uri, ct);
    })
    .Build();
```

`SkipNegotiation = true` skips the negotiate POST (which would carry the token in an Authorization header), driving the client straight at the hub URL with a WebSocket upgrade. The only auth channel is `access_token` in the URL query — if the JWT bearer query-string path regresses, `OnConnectedAsync` never fires, the device never joins `device-{id}`, and `ReceiveNotification` never delivers.

After hub start, the test posts a notification and asserts `ReceiveNotification` fires within 15 seconds with a payload that HMAC-verifies against the seeded tenant signing key.

## RegistrationLoadTests — Closes INFO-M8B-002

The M8.B load harness pre-seeds devices via DB scope to keep the test focused on hub fanout, deliberately skipping `POST /api/devices/register`. That left the registration path itself unexercised under concurrency — which is where the meaningful failure modes live: the unique-index on `RegistrationToken`, concurrent `SaveChangesAsync` against `Tenant.ConsumedCount`, and the `StripeBillingSyncService` no-op contract for tenants without a real Stripe subscription.

The test stands up its own `ApiTestFactory` against the shared `PostgresFixture` for two reasons:

1. The `device-per-hour` rate-limit policy partitions on `RemoteIpAddress?.ToString() ?? "anon"` for unauthenticated registrations. TestServer's `RemoteIpAddress` is null, so all anon traffic shares one bucket. A fresh factory means a fresh rate-limit window — sharing the load fixture's factory would leak budget from prior tests.
2. The factory owns the in-memory rate limiter; tearing it down with the test isolates the shared fixture from concurrent-registration churn.

```csharp
private const int ConcurrentRegistrationCount = 8;  // below the 10/hr "anon" cap

await using var factory = new ApiTestFactory(_postgres.ConnectionString);

var tenantId = await SeedTenantAsync(factory);

var registrations = new Task<HttpResponseMessage>[ConcurrentRegistrationCount];
for (int i = 0; i < ConcurrentRegistrationCount; i++)
{
    var index = i;
    registrations[index] = Task.Run(async () => { /* POST /api/devices/register */ });
}

var responses = await Task.WhenAll(registrations);
```

Assertions:
- All 8 responses are `200 OK`.
- All 8 returned `DeviceId`s are unique (no token collisions).
- `Tenant.ConsumedCount == 8` (no lost writes in the licensing path).
- Eight `Device` rows under the seeded tenant.

Default-skipped, opt-in via `TOAST_TEST_RUN_REGISTRATION_LOAD=1` — same env-gating pattern M8.B established for the 1,000-device fanout variant.
