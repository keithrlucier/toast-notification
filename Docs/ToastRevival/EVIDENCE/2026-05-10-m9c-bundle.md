## What shipped

### 1. INFO-M1-003 — Device registration tenant trust (forward-only)

Pre-this-milestone:
- `Tenant.EnrollmentKey` column existed (M3 hardening) but was opt-in. Tenants without a key allowed open device registration to anyone who knew the TenantId.

After this milestone:
- `AuthController.Register` (both `Initiate` for the M9.A SMS flow + the legacy register path) generates a 24-byte base64 `EnrollmentKey` on every new `Tenant` row. `Convert.ToBase64String(RandomNumberGenerator.GetBytes(24))` → 192 bits of entropy.
- Backfill on 3 existing prod tenants:
  ```sql
  CREATE EXTENSION IF NOT EXISTS pgcrypto;
  UPDATE "Tenants" SET "EnrollmentKey" = encode(gen_random_bytes(24), 'base64') WHERE "EnrollmentKey" IS NULL;
  ```
  Result: all 3 prod tenants (`Colo Solutions`, `test`, `Toast2IT`) now have 32-char base64 keys.
- `TenantSettingsResponse` exposes the key only to admin role (Technicians get `null`).
- New endpoint `POST /api/tenant/enrollment-key/regenerate` (admin-only) for rotation. Generates a fresh 24-byte key and overwrites the row.
- `DeployCommand.tsx` fetches `/api/tenant/settings` on mount; includes `ENROLLMENTKEY=<key>` in the msiexec command and surfaces the value in the parameter chip row.
- `DevicesController.Register` gate semantics preserved (validates when tenant has key set, rejects 403 on missing/mismatched key). Every tenant now has a key, so the gate fires for every registration going forward.
- Agent side already in place pre-this-session: `BootstrapConfig.EnrollmentKey`, `RegistrationService.RegisterAsync` sends it on /register, WiX MSI declares the `ENROLLMENTKEY` property and pipes through `--setup-bootstrap`. Ships next signed agent build.

Backwards-compat note (INFO-M9C-001 carry-forward): v0.3.x agents in the field that don't pass `enrollmentKey` will 403 at register after this milestone. Field install base today = Keith's lab only, which won't re-register until the next signed MSI ships. Acceptable.
